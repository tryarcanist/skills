# Customer report rules

Use the generated `report.md` and `aggregate.json` as the source of all counts.
Inspect the evidence before adopting the suggested actions.

Lead with the decision the history supports and its scope.
A selected PR sample supports conclusions about that sample only.
A complete activity window still does not establish future vendor performance.

For each reviewer, connect the action to verified catches, coverage, noise, overlap, and known costs.
State the tradeoff beside the proposed change.
Unique observed catches can support keeping coverage.

Overlap can support a monitored configuration trial. It does not prove that removal is safe.
No observed catches cannot prove zero value.
Missing delivery surfaces require an undecided result.

Show the claim link and exact code evidence for each conclusion-bearing defect.
Show incorrect claims separately from below-bar and out-of-scope advice.
Expose unknown commits, incomplete sources, exclusions and evaluator limits before a recommendation that depends on them.

Customer prices support conditional savings only.
Do not invent costs, compute costs, hours saved, production bugs prevented, or future defect losses.
A verified fix does not establish that the reviewer caused it.

A quick result promise requires a measured end-to-end run.

The customer can keep their incumbent and decline a sales conversation.
The report must remain useful in that outcome.
The skill sends no report, telemetry, or repository data to a vendor service.

The host agent's model and GitHub access remain subject to the customer's existing setup.
